# Agent API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user can call one of their agents from their own code with a secret per-agent key (`POST /v1/run`, text in, JSON out), manage keys, settings, code samples and the call log on a new API page, and see API usage in Analytics; plus small Python and TypeScript packages.

**Architecture:** The API runs the agent unattended, like automations: the graph-playing loop in `automations/run.py` moves into a shared `agent/unattended.py` used by both. Composio writes get a third mode next to "ask for approval" (chat) and "locked values" (automations): destination values are kept only when they appear in the caller's message (owner's option C). Keys are stored as SHA-256 hashes; the rate limit counts in Redis via a new `cache.hit()`.

**Tech Stack:** FastAPI, async SQLAlchemy, Alembic, LangGraph, redis-py; React 19 + Vite + TanStack Query + the app's `components/ui`; Python 3.9+ stdlib (package); TypeScript + Node 18 `fetch` and `node:test` (package).

**Spec:** `docs/superpowers/specs/2026-11-21-agent-api-design.md`

## Global Constraints

- Endpoint `POST /v1/run`, header `Authorization: Bearer cap_<secret>`, body `{"message": "..."}`; message required, non-empty after trimming, at most 8,000 characters.
- Response `200`: `{"id", "agent_id", "reply", "sources", "tools_used", "duration_ms"}`; `tools_used` items `{"name", "ok", "result"}` plus `"overridden": [...]` when any destination was removed.
- Error body `{"detail": {"code": "...", "message": "..."}}` for every `/v1` error, including validation (code `invalid_request`, status 422).
- Error codes: 401 `invalid_api_key` (missing, unknown or revoked: one message for all), 409 `agent_not_live`, 409 `no_llm_key`, 422 `invalid_request`, 429 `rate_limited` with `Retry-After` (seconds), 502 `agent_failed`.
- Key format `cap_` + `secrets.token_urlsafe(32)`; stored only as SHA-256 hex (unique) + hint = last 4 characters; full key returned once, at creation. At most 10 active keys per agent (409 `too_many_keys`).
- Agent settings: "Actions through the API" default on; "Calls per minute" default 60, 1–600. Without Redis the count is per process; if Redis fails the call is allowed.
- Run limit `RUN_SECONDS` (180 s) from `automations/run.py`. The LLM step cache applies with scope `f"{agent.id}:{agent.llm_provider}:{agent.llm_model}"`.
- Call log keeps message, reply, tools_used, sources, outcome (`ok` or the error code), duration, time, key; rejected calls (401/422/429) are not logged; revoked keys' calls stay; deleting an agent deletes its keys and log.
- Analytics: event `api_call` (`agent_id`, `success`, `duration_ms`); tool calls send `tool_called` with `source="api"`; the Chat tab leaves out `source` `api` as it does `automation`. No message text to PostHog.
- Never log, print or put in analytics or errors a key value. No CORS for `/v1` (the app's CORS middleware stays limited to `frontend_origin`).
- API page copy: create dialog notice "Calls with this key run the agent's actions automatically, without asking: it can …" (naming this agent's actions); after creation "You won't see this key again. Keep it secret, like a password."; under the samples "Keep the key on your server. Never put it in browser or mobile-app code."
- Code samples: Python, JavaScript, TypeScript, Node.js, PHP, Java, Go, C#, cURL; key read from `AGENT_API_KEY`; never the key in a sample.
- Package name `agentplatform` for both (Python import `from agentplatform import Agent`; npm `import { Agent } from 'agentplatform'`) — planner's call, the owner may rename before publishing.
- Packages: `sdk/python` (stdlib only, Python 3.9+, `Agent(api_key, base_url="http://localhost:8000")`, `run(message) -> dict`, `AgentError(status, code, message, retry_after)`), `sdk/typescript` (built-in `fetch`, ESM + `.d.ts`, `new Agent({ apiKey, baseUrl })`, `await agent.run(message)`, `AgentError` same fields); version 0.1.0; no retries; not published.

## Review Focus

1. A destination value that is only *part* of something in the caller's message (message says `bob@x.com`, model sends `bob@x.co` or `x.com`) — must be removed: the match is a whole token, not a substring (test in Task 2).
2. Redis down or slow during a call — the call still runs (rate limit fails open) and costs at most the 0.3 s timeout once per 30 s (test in Task 3).
3. A run that times out or whose model errors — the caller gets 502 `agent_failed`, and the call is still in the log with that outcome (test in Task 3).
4. The PHP, Java, Go and C# samples — nobody runs them in tests; each must be a complete, compiling program that sends the header and body exactly as Python/cURL do (checked by eye in Task 6 against the cURL sample, and by running any toolchain present).
5. The key reaching a log line — creating, using or revoking a key never writes the key or its hash to the log (test in Task 1 and Task 3 with `caplog`).

### Task 6: The API page — code samples, call log, docs

**Files:**
- Create: `frontend/src/components/api/snippets.js`, `frontend/src/components/api/CodeSamples.jsx`, `frontend/src/components/api/CallLog.jsx`, `docs/agent-api.md`
- Modify: `frontend/src/pages/Api.jsx`, `frontend/src/lib/queries.js`

**Interfaces:**
- Consumes: Task 1 `GET /agents/{id}/api/calls`; Task 3 request/response/error shapes; Task 7's package names `agentplatform` (PyPI-style, Python) and `agentplatform` (npm, TypeScript).
- Produces:
  - `snippets(baseUrl: string) -> Array<{ id, label, code }>` for ids `python, javascript, typescript, node, php, java, go, csharp, curl` in that order.
